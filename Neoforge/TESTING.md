# Testing

The port has an automated test suite built on Mojang's **GameTest framework** — tests run
inside a real (headless) Minecraft server with all registries, datapacks, and mod content
loaded, which is exactly the level most porting bugs live at.

## Running the tests

```sh
JAVA_HOME=/path/to/java-21 ./gradlew runGameTestServer
```

Boots a throwaway test server, runs every test, prints a summary, and **fails the build if
any required test fails** (which is what CI runs — see `.github/workflows/build.yml`).

In the dev client (`./gradlew runClient`) you can also run them interactively in any world:

```
/test runall          # run the whole suite in front of you
/test run <name>      # run one test
```

Each test materialises as a small stone platform in the world with a result beacon/lectern.

## What is covered

`src/main/java/dev/cammiescorner/hookshot/gametest/HookshotGameTests.java` — 16 tests:

| Area | Tests |
|---|---|
| **Upgrade data component** | add/remove/duplicate handling; rarity set & restored; durability upgrade doubles max damage & restores on removal; unknown upgrade ids in the component are skipped gracefully; tooltip lists upgrade names |
| **Recipes** | all 24 mod recipes load from the datapack; smithing recipe matches (with the non-vanilla empty template slot) and applies its upgrade; duplicate upgrade yields no result; damage + existing upgrades carry through smithing; dye recipe recolors while preserving damage/upgrades; dye recipe requires a hookshot in the grid |
| **Codec round-trips** | both custom recipe serializers survive `StreamCodec` encode→decode with semantic equivalence (match behaviour + assembled output). The thing most likely to silently break on a version bump. |
| **Hook entity** | using the item spawns exactly one hook entity and sets the `hook_owner` attachment; hook discards (and resets the attachment) when the owner stops holding a hookshot; hook flies, attaches to a wall, and pulls the owner toward it (mock player gains velocity toward the hook) |

### Known limitations

- **Client-side code is untested** — rendering (chain/entity models), item color tinting, and
  the `using_hook` model predicate can only be eyeballed in `runClient`.
- **Config variations are untested** — the STARTUP config is loaded once with defaults; tests
  assume `default_durability=512`, multipliers ×2/×1.5, classic mode off.
- **The attachment sync packet isn't exercised** — GameTest mock players aren't real
  `ServerPlayer` connections, so `HookSyncPayload` never fires in tests.

## Writing a new test

Add a `public static` method to `HookshotGameTests` (or a new class next to it):

```java
@GameTest(template = PLATFORM)
public static void my_new_test(GameTestHelper helper) {
    // ... helper.assertTrue(...), helper.succeedWhen(...), etc.
    helper.succeed(); // every test must explicitly succeed
}
```

Things that will bite you (they bit this suite):

1. **Namespace filtering** — NeoForge only runs tests whose namespace is in the
   `neoforge.enabledGameTestNamespaces` system property (set in `build.gradle` for the
   `gameTestServer` and `client` runs). A test's namespace comes from `@GameTestHolder("hookshot")`
   on the class (which also auto-registers it) — **not** from the `template` string. Without it,
   tests silently land in the `minecraft` namespace and get filtered out
   (`No test functions were given!`).
2. **Template paths** — with `@PrefixGameTestTemplate(false)` the structure resolves to
   `<holder-namespace>:<template>`, so `template = "platform"` →
   `data/hookshot/structure/platform.nbt`. Don't put the namespace inside the template string.
3. **Tag ingredients flatten over the network** — `Ingredient.CONTENTS_STREAM_CODEC` resolves
   `#hookshot:hookshots` into a concrete item list, so decoded recipes are *semantically* equal,
   never JSON-identical. Compare behaviour, not serialized form.
4. **Mock players aren't ticked** — `helper.makeMockPlayer()` players are not added to the
   server tick loop: velocity set on them sticks (good for assertions) but they never move,
   and they aren't `ServerPlayer`s (no network). Discard them at the end of the test.

The platform structure (`platform.nbt`, 9×4×9 smooth stone floor) was generated by a small
NBT-writing script; any vanilla structure NBT placed under `data/hookshot/structure/` works
as a template.
